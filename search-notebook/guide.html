核心目标：独立发现

纯名称搜索只给名字；名称加功能题提供了更多任务线索，要按题号另外统计。无品牌需求题只说任务，不提供名称、别名、作者或网址。网址读取单列诊断。发现主体与整条描述是否准确，也分别记录。

先保存一条真实记录

在目标 AI 产品正常提问，等待回答完成，再把完整原文和实际链接粘贴到记录器；填写环境、状态和人工核对，点击“保存这条证据”。记录保存在当前浏览器 localStorage。换浏览器不会删除旧浏览器记录，也不会自动同步；需要导出 JSON 并在目标浏览器导入。工具不自动代问或替你验证事实。

1. 先锁定对象和基线

默认对象是本站“拾玖搜证台”，一个已经实现的本地记录工具。原始 q1 候选集共 24 题，最初核心设计为 S01–S04（A 推荐）、N01–N03（B 事实）、X01–X02（C 排除）、T01（D 使用），共 10 题、每题计划 2 次。计划不代表这些题已全部执行；每个实际批次按当时冻结的题号与次数记录。D01–D02 是额外读取诊断。后来新增的 q2 澄清需求题另建基线，不替换 q1 负例。题目由本项目构造，不代表真实用户调研。

记录器支持替换被测名称，但不同对象需要自己准备真实的事实卡、别名和适用限制。不要只改名字就复用本站的产品事实。

2. 在豆包中手动采样

  1. 打开记录器，选问题并复制。先记下实际产品模式、是否联网、登录情况、地区。看不到的字段填“未知”。
  2. 每次创建全新对话。名称和需求题不要先粘贴网址、相关截图、本站介绍，也不要追问暗示正确答案。
  3. 等回答完成，原样保存正文、引用链接和截图。未找到也是有效观察；登录弹窗、网络失败等另记为技术失败。
  4. 将原文与模型给出的链接填回工具。逐个打开引用，核对主体、至少两条未在问题里给出的事实和推荐行为，填写标记及错误备注，最后点击“保存这条证据”。仅录入表单不是已经保存。
  5. 按本批次预先确定的次数执行，同题下一次另开全新对话；保持该批次的问题集、事实卡快照和环境条件一致。f1、f2 或 q1、q2 都应写明，不能把某个历史版本固定当作当前版本。发送后暂未看到确认时，保留原标签和事件，先只读核对，避免重复发送；同一原对话后来完成，只计一条最终回答。

3. 怎样才算达标？

路径必要证据单独统计
纯名称发现只给名称；主体正确；至少两条未给定事实；当次实际来源支持N01，单独统计
名称加条件或功能主体与具体事实有支持来源；逐项记下描述错误N02／N03 等，不能算成 N01 的命中
需求推荐不给目标线索；确实推荐且适用；事实与来源同样经过核对q1 各需求题分题号；q2 另列
网址读取给出指定 URL，读取正文并核对D01–D02，诊断项
不适用排除对不适用需求不推荐本工具，并有正确解释X01–X02，边界项

名称题达到主体与两项事实的发现标准，不代表回答每一句都正确；整条描述“对”“部分错”“错”“未涉及”应另外标记。T01 是使用建议题，保留操作错误记录，不与纯名称或需求推荐混算。当前结果见 已复核实测现状。

完整回答和明确拒答进入各自路径的有效样本分母；无命中、来源错误、事实错误都不能删掉。技术失败、未完成、原文缺失或独立发现条件不满足的记录单列。不同批次、平台、入口、模型模式、联网、登录、地区分开统计。

比例描述的是这一组固定问题下的观察，不是全平台搜索占有率。没有样本时显示“未采样”。练习区全部为模拟，不能作为成效展示。

4. 没搜到时怎么改？

  1. 先检查不登录是否能打开页面，正文是否直接包含明确名称、用途、真实能力和限制。
  2. 用 D01、D02 看页面识别是否正确。读取测试放在独立对话里，不污染名称和需求测试。
  3. 再检查公开来源是否被发现；页面名称、实体说明、内链、事实站、文章、sitemap 是否一致。结构化数据是辅助表达，不是收录开关。
  4. 只有站内信息准确且可读后，再考虑补一个真实平台的公开介绍或使用教程。该步骤需对应平台账号与发布权限，不能把未发布稿算外部来源。
  5. 一次只改少量明确问题；记录发布时间、URL 和版本，按同一问题集复测。不承诺等待几天必然命中。

记录器保存什么、哪些步骤需要人完成？

  • 截图在自己的文件夹保存，备注只写文件名；工具没有截图附件或自动截图功能。
  • 工具检查网址格式，使用者逐个打开来源并核对事实，再填写人工复选项；没有自动可达性或语义核验。
  • 测试路径由name、scene、url等显式字段决定，D/N/S字母只是题号约定；纯名称与名称加功能仍按题号区分。
  • 当前CSV的题集／事实卡列固定q1／f1，交付前按实际快照复核；如修正，保留原导出并另存校正副本。发现达标和整条回答准确性也需另外核对。
  • 每题新对话，单独记录账号记忆设置，未核实就写未知；不同设置的样本分批。可把这些条件写进备注，另留题集和事实卡快照。

5. 如何带回 GEO 医生工作台

CSV 使用 GEO 医生的 runs 表头，可作为采样输入；JSON 保留完整回答和复核字段。点击“GEO 医生文件清单”会下载一个 JSON，其中 rawFiles 是建议写出的文件路径及内容，包含 runs.csv、report.md、raw/*.md。

本地源码附带拆包脚本：把导出的文件放在项目外安全位置，运行以下命令，将原文与 CSV 写入一个全新的目录；脚本只接受固定安全路径，不覆盖已有文件。然后将该目录中 runs.csv 及 raw 目录提供给 GEO 医生复核。

兼容 CSV 是交换格式，不代表已自动连接工作台。App 采样和 API 采样分开；没有启用联网检索的模型 API，不能用来判断豆包 App 的搜索可见性。

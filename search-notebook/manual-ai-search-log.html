打开记录器功能事实使用教程实验现状

作者：拾玖 · 更新：2026-11-04

不用 API，怎样记录和比较豆包搜索测试结果？

拾玖搜证台是一个真实可用的浏览器本地 AI 搜索实验记录器。用户手动复制豆包等产品的回答与引用链接，按批次保存、核验和导出；工具不自动提问，也不调用模型 API。

先明确你要比较什么

小规模 GEO 实验可以先固定问题，分别记录优化前和优化后的回答。给网址读取、只按名字搜索、不带品牌的需求推荐，是三种不同测试；记录和统计应当分开。

表格也能做这件事。如果你只测一两题，普通表格通常已经够用。拾玖搜证台更适合希望统一保存完整原文、来源、环境和人工判定，并交换 JSON 备份的小团队。它没有自动差异高亮或语义评分。

一次实际操作分五步

第一步：打开记录器，选择真实采样，填写被测对象、批次和测试路径。

第二步：在豆包新建对话，提交固定问句。名称题只给名称；需求题不给被测名称、网址或作者线索。

第三步：把完整回答粘贴回来，并记录豆包实际给出的来源链接；自己后来找到的网页不能冒充当次引用。

第四步：填写平台、网页或 App 入口、实际模式、日期、登录和联网状态。不知道的条件记为未知。打开来源核对主体与具体事实，再填写人工复核标记。

第五步：导出 JSON 备份、CSV 表格或 Markdown 报告。下一轮保留原题并换批次，分别比较名称发现与需求推荐；技术失败单列。

记录应该包含哪些字段

最少保存：问题原文、回答原文、模型引用链接、采样时间、平台入口、实际模式、登录与联网状态、批次，以及人工核对结论。

名称发现需要主体正确、至少两条未在问句中给出的具体事实和支持来源。需求推荐还需要工具确实适用，并被回答推荐。名字出现一次，不自动等于成功。

给定 URL 的读取是诊断，不能混进独立发现的成功率。明确未找到也应保留；网络报错和验证阻挡则作为技术状态另列。

本地保存与文件交换

记录保存在当前浏览器 localStorage，应用没有上传采样记录的接口。在线访问托管页面和打开外部引用仍会产生网络请求；这与采样内容是否上传是两件事。

JSON 保留完整回答，可在另一浏览器合并导入，按记录 id 去重，不覆盖旧记录；单个导入文件最多 3 MB、2000 条。CSV 使用 GEO 医生表头，Markdown 适合阅读汇报。

清理站点数据、换浏览器或结束隐私模式可能丢失本地记录，所以每轮都应导出 JSON。它不提供云端恢复、服务器权限管理和多人实时协作。

截至 2026-11-04，实验实际到了哪一步

项目网页和记录器已经上线。本次真实豆包网页端基线包含一条名称题和两条无品牌需求题，三条均未形成项目独立发现：名称题明确表示未检索到，需求题推荐了其他工具。样本很小，不据此推断平台总体表现。

另有两条给网址的诊断，回答复述了项目具体事实，但存在声明无法访问指定子路径、来源链接截断或未提供可点击来源的问题，不能当成完整引用成功。

这篇文章是项目维护者自己的使用说明，不是第三方测评。公开内容可以作为待验证来源，不保证任何平台收录、推荐或排名。完整回答和账号相关信息保留在本地实验记录中。

与 GEO 医生的关系

GEO 医生是 Fangx-AI 的开源项目，本 demo 使用其事实卡、问题管理、事实站生成、发布检查和诊断流程。浏览器本地记录器与本说明是本项目新增实现。

记录器自身不会自动打开、登录或代问豆包。实验执行时另外使用浏览器自动化采样，不应把实验人员的操作能力说成工具已经内置的产品功能。
